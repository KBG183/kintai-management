| F-003 | Fallback Strategy: Silent Corruption Risk | P1 | WARN | **Spec 04:**<br>"Fallback logic: If report.json verification fails or is invalid, falls back to legacy v1 report.md regex parser." | **Security & Integrity Risk:** Falling back to a regex-based parser for a structured JSON schema is dangerous. If the v2 JSON fails due to a malicious or buggy payload, the v1 parser might extract incorrect data or miss critical security flags, leading to a "silent pass" of a failing audit. **Recommendation:** Do not silently fallback. | F-004 | Token Calculation: Context Truncation Risk | P1 | WARN | **Spec 07:**<br>"Proposal to change character-to-token formula from / 3.0 to / 4.0 and increase NumCtx to 32768." | **Silent Truncation Risk:** Changing the divisor from 3.0 to 4.0 assumes a more efficient tokenization ratio. However, for Japanese text (which is dense in tokens per character) or complex code, 1 character ≈ 1 token is often closer to reality than 1 char ≈ 0.25 tokens. If the actual token count exceeds the `num_ctx` (32768) because the estimate was too low, Ollama will silently truncate the context, potentially cutting off the end of the prompt (where the code to be audited often resides) or the system instructions. **Recommendation:** Do not rely on a static character-to-token ratio for Japanese/Code. Use a proper tokenizer library (e.g., `tiktoken` or Ollama's internal tokenizer) to count tokens accurately before sending the request. If a static ratio is kept, use a conservative estimate (e.g., / 2.0) and add a hard check that rejects requests if the estimated tokens exceed 90% of `num_ctx`. |

| F-007 | Japanese Labor Law: Night Work Calculation Logic | P1 | FAIL | **Spec 02 (Judgment Constitution):**<br>"Night (22:00~05:00) + Overtime (8h excess) duplicate addition: 25% + 25% = 50%" | **Incorrect Legal Interpretation:** Under Japanese Labor Standards Act Article 37, the premium rates are additive but capped. <br>1. Night Work (22:00-05:00): +25% (or 35% if >8h night work).<br>2. Overtime (>8h/day): +25% (or 50% if >45h/month).<br>3. **Concurrent Night + Overtime:** The premiums are added. 25% (Night) + 25% (Overtime) = **50% premium** (Total pay = 150% of base rate).<br><br>**However**, the spec says "25% + 25% = 50%". This is correct for the *premium* portion. But the spec in File 02 also mentions "Total dwell time (525 min) vs Actual labor time (480 min, rest 45 min deducted, overtime 0 min)". This specific example is confusing. If the total time is 525 mins (8h 45m), and 45 mins are rest, the work time is 8h. There is **no overtime** if the standard day is 8h. Overtime only starts *after* 8h. If the employee worked 8h 45m, and 45m was rest, the *work* time was 8h. Thus, Overtime = 0. Night work premium applies to the night hours. The spec's example seems to conflate "dwell time" with "work time". **Recommendation:** Clarify that Overtime is calculated based on *actual work hours* after deducting rest periods. If work hours <= 8h, Overtime = 0. Night work premium applies to hours worked between 22:00-05:00. The combined premium is only applicable if the specific hour is *both* night work AND overtime. |

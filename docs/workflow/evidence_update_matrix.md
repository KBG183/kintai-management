# 개선 작업 완료 시 증적 갱신표

개선 작업은 코드·테스트 결과만으로 완료 처리하지 않는다. 아래 적용 가능한 항목을 모두 갱신한 뒤 완료 보고한다.

| 작업 결과 | 반드시 갱신할 파일 또는 경로 | 규칙 |
|---|---|---|
| 실행·성공·실패·보정 | `docs/audit_runs/<run-id>/` | 콘솔 원문, JUnit XML, manifest 또는 분류 보고서 보존 |
| 한국어 사실 기록 | `docs/portfolio_audit_evidence_KO.md` | 실제 확인 사실과 미검증·BLOCKED를 구분해 누적 |
| 일본어 사실 기록 | `docs/portfolio_audit_evidence.md` | 한국어 기록과 동일한 사실·상태·경로를 병행 반영 |
| 요구사항·판정 상태 | `docs/rtm_ledger.md` | ID, 상태, 근거, 보류 사유 갱신 |
| 세션 인수인계 | `docs/handoff/YYYYMMDD_HHmm_<operator>_handoff.md` | 목표, 완료·진행·실패, 결정, 실제 경로, 다음 단계, 함정 기록 |
| 운영 규칙 변경 | `AGENTS.md`, 관련 `docs/workflow/*.md` | 다음 작업자가 따를 규칙으로 명문화 |

## 완료 게이트

- 기능 코드 또는 테스트 변경이 있으면 변경 파일과 테스트 결과를 기록한다.
- 실행 실패가 있으면 실패 원문과 원인 분류를 기록한다.
- 한국어·일본어 증적서의 상태와 수치가 일치하는지 확인한다.
- 실제 실행하지 않은 AI·환경·모델을 사용한 것처럼 기록하지 않는다.
- 검증하지 못한 항목은 `미검증` 또는 `BLOCKED`로 유지한다.
- 적용할 문서가 없는 단순 조사도 인수인계 또는 진행기록에 결과를 남긴다.

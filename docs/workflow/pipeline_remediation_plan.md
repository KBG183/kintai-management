## 1. 📌 개요 및 핵심 수정 사항 (v1.1 ➔ v1.1.1)

최종 검토에서 지적된 8대 결함을 전적으로 수용하여 계획서를 v1.1.1로 갱신합니다.

### v1.1.1 핵심 수정 내역
1. **Java 버전 불일치 정정**: `build.gradle` 실측 확인 결과 Java 17(toolchain)이므로, 문서의 모든 "Java 21" 표기를 **Java 17**로 전면 수정 (`F-05`).
2. **D-01 및 W0-3 작업 ID 분리**: D-01(테스트 실행 강제)을 `W0-3`으로 명확히 단독 배정하고, 감사 원장 생성을 `W0-4`로 분리 (`D-01`).
3. **불완전 실행 폴더 보존 (`G-02`)**: `.done` 센티널이 없는 실패/중단 실행 폴더도 자동 삭제하지 않고 `INCOMPLETE` / `FAILED` 라벨로 영구 보존하여 실패 증거 확보.
4. **E-01/E-03 쓰기 경로 전수 식별 및 DB 제약 강화**:
   - `docs/invariants.md`를 신설하여 단순 타각 외 시프트 확정, 관리자 대리 수정 등 모든 근태 변경 경로 목록화.
   - E-03: `clock_out >= clock_in` 외에 `total_break_minutes >= 0` 및 체류 시간 초과 방지 DB CHECK 제약 포함.
5. **G-04 과거 동시성 PASS 전수 소급 재분류**: Day 2, 3, 5, 7, 8의 동시성 항목 전체를 `PASS-STATIC`으로 소급 분류하고, Day 10 Testcontainers 통과 시 승격 명시.
6. **작업 의존 순서 정정**: 번들러(`scripts/make_audit_bundle.ps1`)를 Git Hook보다 먼저 구축하고, `ACCEPTED_RISK` 처분 시에도 사용자 승인 강제 (`A-05`).
7. **개발 일정 병행 구조화**: 과도한 인프라 선행으로 인한 본 기능(Day 9 엑셀) 지연을 방지하기 위해, 선행 필수 5대 작업 완료 후 Day 9 개발과 감사 인프라를 실용적으로 병행.

## 2. 🚦 Day 8 커밋 전 선행 임시 절차 (Pre-Commit Gate for Day 8)

사용자가 명시적으로 "커밋해라"라고 승인하기 전까지 커밋을 일체 보류하며, 사전에 아래 5단계를 순차적으로 실행하여 기준선을 확립합니다:

1. **현재 코드베이스 테스트 기준선 확인 (`D-01`)**:
   - `./gradlew clean test`를 실행하여 5개 단위 테스트의 통과 여부 및 결과를 확인.
2. **`audit_with_hermes.ps1` v1.1 즉시 패치 (`B-01`, `B-02`, `B-03`, `B-06`, `B-07`)**:
   - 실패 시 `exit 1` 강제, 고유 타임스탬프 디렉터리 출력, 컨텍스트 초과 추정 검사, 타임아웃 10분, 실패 폴더 보존 로직 적용.
3. **패치된 v1.1 스크립트로 Day 8 번들 재감사 실행**:
   - 고유 디렉터리(`docs/audit_runs/`)에 새 원본 리포트와 메타데이터 생성.
4. **사용자에게 Qwen 원본 리포트 전문 직접 제시 및 확인 (`A-11`)**:
   - 요약문 뒤에 숨지 않고, 생성된 영문 원본 리포트 전문의 위치와 주요 내용을 사용자에게 직접 대조 보고.
5. **사용자의 명시적 "커밋해라" 지시 대기**:
   - 사용자가 원본 리포트와 테스트 결과를 확인하고 명시적으로 "커밋해라"라고 명령할 때까지 커밋·푸시 일체 실행 금지.

## 3. ⚡ Wave 0: 선행 필수 과제 (Day 8 마감 및 정합성 수립)

### [W0-1] 감사 스크립트 엔진 v1.1 패치 (`audit_with_hermes.ps1`)
- **대응 결함 ID**: `B-01` (종료코드 0), `B-02` (컨텍스트 검사), `B-03` (모델 불일치), `B-06` (타임아웃/재시도), `B-07` (메타데이터)
- **구체적 수정 사항**:
  1. API 통신 실패, 빈 응답 수신 시 무조건 `exit 1` 반환.
  2. 일시적 네트워크 단절에 한해 최대 2회 재시도(지수 백오프) 적용.
  3. `docs/audit_runs/<UTC_TIMESTAMP>_<FILE_SHA8>/`에 고유 저장. `.done` 센티널이 없는 실행도 삭제하지 않고 보존하여 실패 증거 유지 (`G-02`).

  5. `Timeout = 600000`(10분), `keep_alive = "30m"`. 실행 완료 시 `audit_run.json` 영구 보존.

### [W0-2] 공식 감사 게이트 정책 문서 수립 (`docs/audit_gate_policy.md`)

## Day 10 실행 기준 결정 기록

- Docker Desktop이 개발 환경에 설치되어 있지 않아 Testcontainers(MySQL 8.4) 실행은 보류한다.
- Testcontainers 전용 의존성과 테스트는 프로젝트에서 제거하여 실행되지 않는 미완성 구성을 남기지 않는다.
- Day 10의 실제 검증 기준은 현재 운영 중인 로컬 MySQL 26.7.0 기반 통합 테스트와 기존 JUnit 증적으로 전환한다.
- MySQL 8.4 재현성 항목은 `R-05` 잔여 위험으로 유지하며, 해당 항목을 `PASS-VERIFIED`로 판정하지 않는다.
- 향후 CI 또는 배포 재현성이 필요해질 때 Docker/Testcontainers를 별도 작업으로 재개한다.

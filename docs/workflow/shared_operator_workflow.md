# Codex · Antigravity 공용 운영 규칙

> 이 문서는 과거 큐 실험과 인수인계 기록을 보존한다. 현재 기준은 `AGENTS.md`와 `docs/workflow/operating_policy_v2.md`이며 Codex와 큐 워커를 자동 호출하지 않는다. 아래 큐 절차는 사용자 요청이 있을 때만 별도로 검토한다.

## 운영 원칙

이 프로젝트는 Codex와 Antigravity 중 **항상 한쪽만 활성 오퍼레이터**로 사용한다.

- 평상시: 현재 사용 중인 AI 하나만 프로젝트 파일을 수정한다.
- 사용자님이 교체를 결정한 경우에만: 작업 상태를 파일에 남긴 뒤 다른 AI로 인계한다.
- 두 AI를 동시에 실행하여 같은 파일을 수정하지 않는다.
- Qwen 27B는 두 오퍼레이터가 공용으로 사용하는 독립 감사관이다.
- Java/Spring 기능 코드, DDL, SQL, 설정 SSOT는 사용자가 명시하지 않는 한 자동 수정하지 않는다.

## 역할 분리

| 역할 | Codex 또는 Antigravity | 공용 Qwen 27B |
|---|---|---|
| 설계·구현 | 활성 오퍼레이터 1개 | 수행하지 않음 |
| 파일 수정 | 활성 오퍼레이터 1개 | 수행하지 않음 |
| 독립 감사 | 요청 작성·결과 판독 | 실제 감사 실행 |
| 최종 승인 | 사용자 | 판정 근거 제공 |

## 작업 시작

활성 오퍼레이터는 작업 전에 다음을 확인한다.

1. `git status`와 최근 변경 파일 확인
2. `docs\handoff\` 또는 최신 작업 기록 확인
3. 다른 오퍼레이터가 작업 중인지 확인
4. 이번 작업의 수정 범위와 금지 범위 선언

## 작업 중

- 활성 오퍼레이터만 원본 파일을 수정한다.
- Qwen 요청은 `docs\codex_queue\pending\`에 생성한다.
- Windows 큐 워커는 원격 endpoint `http://100.111.193.94:11434`만 사용한다.
- 결과는 `completed` 또는 `failed`의 고유 request ID 폴더에 저장한다.
- 기존 감사 결과를 새 감사 결과처럼 재사용하지 않는다.

## 사용자님이 교체를 결정했을 때의 인계

사용자님이 현재 오퍼레이터를 교체하기로 결정하면, 현재 오퍼레이터는 다음 정보를 파일에 기록한 뒤 중단한다.

- 완료된 작업
- 진행 중인 작업
- 실패한 시도와 오류 원문
- 수정된 파일의 실제 경로
- 아직 수정하지 않은 파일
- 확정된 결정과 근거
- 다음 오퍼레이터의 첫 작업
- 완료 기준

인계 파일은 다음 형식을 사용한다.

```text
docs\handoff\YYYYMMDD_HHmm_<operator>_handoff.md
```

다음 오퍼레이터는 인계 파일과 현재 파일 상태를 먼저 읽고, 같은 작업을 처음부터 반복하지 않는다.

## 오퍼레이터 교체 순서

교체 여부와 시점은 사용자님이 판단한다. Codex나 Antigravity가 토큰 부족을 임의로 추정하여 교체를 선언하지 않는다.

1. 현재 오퍼레이터가 파일 저장을 완료한다.
2. 실행 중인 테스트와 Qwen 요청이 종료됐는지 확인한다.
3. `docs\codex_queue\pending\`에 미처리 요청이 있는지 확인한다.
4. 인계 파일을 작성한다.
5. 현재 오퍼레이터의 작업을 종료한다.
6. 다른 오퍼레이터가 인계 파일, `git status`, 관련 manifest를 읽는다.
7. 다른 오퍼레이터가 이어서 작업한다.

## Qwen 워커 운영

Windows PowerShell에서 다음 워커를 하나만 실행한다.

```powershell
cd C:\dev\kintai
.\scripts\process_codex_queue.ps1 -Watch -PollIntervalSec 3
```

- 워커는 한 번에 하나만 실행한다.
- `.qwen_remote.lock`이 있으면 중복 실행하지 않는다.
- Antigravity의 Hermes 실행 중에는 큐 워커를 동시에 실행하지 않는다.
- 로컬 `qwen2.5:7b`로 폴백하지 않는다.

## 완료 판정

작업 완료는 다음 조건을 모두 만족할 때만 선언한다.

- 기능 코드와 문서 변경 범위가 보고 내용과 일치한다.
- 한국어 증적서 `docs\portfolio_audit_evidence_KO.md`와 일본어 증적서 `docs\portfolio_audit_evidence.md`를 같은 작업 단위에서 병행 갱신한다.
- 두 증적서의 Day 번호, 버전, 날짜, 테스트 수치, 실행 ID, SHA-256, 판정이 서로 일치한다.
- 한 언어판만 갱신된 상태에서는 해당 증적 작업을 완료로 선언하지 않는다.
- 정상 테스트와 실패 테스트가 모두 확인됐다.
- Qwen 결과가 독립 실행 결과로 보존됐다.
- `manifest.json`과 실제 파일 SHA-256이 일치한다.
- 미해결 항목과 사용자 승인 대기 항목이 명시됐다.

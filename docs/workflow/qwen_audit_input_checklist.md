# Qwen 독립 감사 입력 사전검증 체크리스트

`scripts/validate_qwen_audit_input.ps1`은 매니페스트를 제공한 경우 일부 형식과 파일 존재 여부를 확인한다. 체크리스트 전 항목, 파일 내용의 적합성 및 실행 결과의 진위를 자동으로 보증하지 않는다. Hermes 호출에 매니페스트를 지정하지 않으면 사전검증이 실행되지 않는다.

`scripts/audit_hermes_preflight.ps1`을 직접 호출하면 매니페스트를 검사한 뒤 기존 사용자 계정 Hermes 스크립트를 호출한다. 기존 Hermes를 직접 호출하는 다른 경로는 이 검사기를 자동으로 거치지 않는다. 주소와 모델을 지정하지 않으면 기존 Hermes 스크립트의 기본값을 따른다. 매니페스트의 상대 증적 경로는 호출 시 현재 작업 디렉터리를 기준으로 해석된다.

래퍼는 `docs/audit_runs/preflight_<고유번호>/`에 번들과 매니페스트 복사본 및 검증 결과를 보존한다. 통과 시 복사본을 Hermes에 전달하며, 출력 디렉터리를 지정하지 않으면 같은 폴더 아래에 결과를 저장하고 파일별 해시를 기록한다. 별도 출력 경로를 지정하면 결과가 그 경로에 남으므로 함께 보존해야 한다. 입력 생성 실패나 프로세스 강제 종료 시 일부 증적이 없을 수 있다.

검증기는 비어 있는 증적, 잘못된 JUnit XML, 실패·오류가 있는 JUnit 및 전부 건너뛴 테스트를 거부한다. 테스트 대상과 요구사항의 관계, 로그의 진실성, 일부 건너뛴 테스트의 영향은 자동 판정하지 않는다.

Qwen 27B를 호출하기 전에 감사 입력이 실제로 전달 가능한지 확인한다. 조건을 하나라도 충족하지 못하면 Qwen 호출 결과를 감사 결과로 인정하지 않고 `INPUT_INCOMPLETE`로 기록한다.

## 필수 확인

- [ ] 감사 번들 파일이 존재한다.
- [ ] 감사 번들 크기가 0바이트가 아니다.
- [ ] 감사 대상 코드 또는 문서가 번들에 포함되어 있다.
- [ ] 관련 SRS 요구사항 ID가 포함되어 있다.
- [ ] 관련 RTM 항목과 완료 기준이 포함되어 있다.
- [ ] 실행 명령과 실제 테스트 결과가 포함되어 있다.
- [ ] 실패한 실행과 수정 내역이 누락되지 않았다.
- [ ] 환경 제약과 검증 범위가 명시되어 있다.
- [ ] 독립 감사 지시문이 번들 본문과 분리되어 있다.

## 결과 인정 조건

Qwen 결과는 다음 조건을 모두 만족할 때만 독립 감사 결과로 인정한다.

1. 입력 번들의 SHA-256이 기록되어 있다.
2. 결과 원문과 결과 해시가 보존되어 있다.
3. Qwen이 번들에 포함된 실제 파일·로그·테스트를 근거로 판정했다.
4. `PASS`, `WARN`, `FAIL`, `N/A`와 근거가 항목별로 분리되어 있다.
5. 감사 범위를 벗어난 항목은 `N/A` 또는 `UNVERIFIED`로 표시되어 있다.

## 금지 사항

- 번들 파일 경로만 전달하고 본문이 전달됐다고 가정하지 않는다.
- 실행하지 않은 테스트를 성공 증거로 넣지 않는다.
- Qwen이 보지 못한 파일을 근거로 Qwen 판정을 해석하지 않는다.
- 감사 결과가 없는데 `VERIFIED`로 변경하지 않는다.
